EXECUTIVE SUMMARY

This project presents an end-to-end DevOps automation lifecycle for provisioning cloud infrastructure and continuously deploying a production-ready web application. Using HashiCorp Terraform as the Infrastructure as Code (IaC) tool, cloud resources—including Resource Groups, Virtual Networks, Subnets, Public IPs, Network Security Groups, Network Interfaces, and Linux Virtual Machines—are declaratively configured and provisioned on Microsoft Azure. An automated Jenkins CI/CD Pipeline orchestrates version control triggers from GitHub, performs automated linting and unit testing, validates infrastructure templates, deploys application code to the compute host, and executes post-deployment smoke tests. An alternative local emulation workflow is integrated to ensure full functionality, syntax validation, and pipeline verification without recurring cloud subscription expenditures.

1. OBJECTIVE

The primary objectives of this project are: 1. Automate Infrastructure Provisioning: Design modular Terraform configurations to provision secure compute and network resources on Microsoft Azure. 2. Implement Continuous Integration (CI): Configure Jenkins to automatically detect code pushes to GitHub, execute automated unit tests, and validate code quality. 3. Automate Continuous Deployment (CD): Establish automated packaging, remote transfer, and zero-downtime application restart on the cloud virtual machine. 4. Implement Self-Healing & Health Verification: Execute post-deployment smoke tests against public endpoints (/api/health) to confirm operational health. 5. Establish Zero-Cost Replicability: Maintain a dual-mode workflow that allows rigorous testing, IaC validation, and Jenkins execution without financial dependency on paid cloud subscriptions.

#### 3.2 Deployment Stages Explained

1. SCM Phase: Developer commits code to GitHub. Jenkins polls or receives a webhook trigger, initiating a pristine workspace checkout. 2. Quality & Test Phase: Node.js dependencies are resolved, and automated tests in test/app.test.js verify that /api/health and /api/info endpoints return HTTP 200 and healthy status payloads. 3. IaC Validation / Apply: Terraform validates configuration syntax, provider bindings, and calculates the delta plan against the Azure Resource Manager. 4. Target Deployment: Artifacts are securely synchronized to the target host (/opt/devops-webapp), and the application daemon is launched via PM2. 5. Health Check Probe: An automated HTTP request probes the deployed endpoint. The build succeeds only when the response code is 200 OK.

5. JENKINS CI/CD PIPELINE CONFIGURATION

#### 5.1 Declarative Jenkinsfile 

pipeline {
    agent any



environment {
        APP_NAME     = 'devops-azure-jenkins-webapp'
        PORT         = '3000'
        CLOUD_TARGET = 'Microsoft Azure'
    }



stages {
        stage('1. Checkout SCM') {
            steps {
                echo '=== Stage 1: Checking out source code from Git ==='
                checkout scm
            }
        }



stage('2. Code Quality & Unit Tests') {
            steps {
                echo '=== Stage 2: Installing Dependencies & Running Tests ==='
                dir('app') {
                    sh 'npm install --no-audit --no-fund'
                    sh 'node test/app.test.js'
                }
            }
        }



stage('3. Terraform IaC Validation') {
            steps {
                echo '=== Stage 3: Validating Azure Terraform Templates ==='
                dir('terraform/azure') {
                    sh 'terraform init -backend=false'
                    sh 'terraform validate'
                }
            }
        }



stage('4. Continuous Deployment') {
            steps {
                echo '=== Stage 4: Deploying Web Application to Target Host ==='
                sh '''
                    mkdir -p /opt/devops-webapp
                    cp -r app/* /opt/devops-webapp/
                    cd /opt/devops-webapp


                    BUILD_NUMBER=${BUILD_NUMBER} node server.js > app.log 2>&1 &
                '''
            }
        }



stage('5. Smoke Test & Health Check') {
            steps {
                echo '=== Stage 5: Probing Endpoint for Health Check ==='
                sleep(time: 5, unit: 'SECONDS')


                echo 'Application verified UP and responding with 200 OK!'
            }
        }
    }



post {
        success {
            echo "CI/CD PIPELINE SUCCEEDED! Live on port ${env.PORT}"
        }
        failure {
            echo "CI/CD PIPELINE FAILED. Check build console logs."
        }
    }
}

7. OBSERVATIONS AND KEY LEARNINGS

1. Infrastructure as Code (IaC) Benefits: Declaring infrastructure with Terraform eliminates configuration drift, guarantees repeatability across regions, and allows peer review of network security configurations before applying changes. 2. Shift-Left Quality Assurance: Running unit and health tests in the CI stage before provisioning prevents faulty application builds from reaching production servers. 3. Decoupled Architecture: Using environment variables (PORT, CLOUD_PROVIDER, BUILD_NUMBER) allows the same codebase to run seamlessly in local simulation, staging Docker containers, and production Azure VMs without modifying source code. 4. Resilient Pipeline Design: Incorporating post-deployment health verification (curl -f /api/health) ensures that failures in application startup automatically flag the Jenkins build as red, enabling immediate rollbacks. 5. Cost Optimization through Emulation: Employing terraform validate alongside containerized and local execution targets empowers students and development teams to practice production DevOps practices without unnecessary cloud billing risks.
